# debut architecture

One Rust engine compiles natively for desktop and to WebAssembly for the browser,
under one shared TypeScript UI. Roughly 80–90% of the code is shared; only the
platform layer differs per target. Requirements: *Video Editor Requirements*
(claude.ai/code/artifact/92b88caa-d0f5-41d4-869d-6313438ad4fb).

## Layering

```
apps/ui (TypeScript/React)          one UI for both targets
   │                 │
apps/desktop      apps/web           Tauri IPC         wasm-bindgen
   │                 │
          debut-engine               api::Session (the command surface), playback, session
   │  │  │  │  │  │  │  │
   project  command  media  timeline  audio  render  graphics  export  collab
   │                                                                   │
          debut-platform             six traits; no feature logic
   │                 │
platform-native   platform-web       FFmpeg/CoreAudio/OpenFX   WebCodecs/OPFS/AudioWorklet
```

Rules enforced by the crate graph:

- `debut-core` and `debut-platform` have no OS, GPU or codec dependencies and compile on every target (PLT-01).
- Engine crates depend on `debut-platform` traits only, never on an implementation crate (PLT-02). They reach files, threads, time and fonts only through `Platform`.
- The project is mutated only through `debut-command`, so every edit is undoable, journaled and syncable (TL-11, NFR-05, COL).
- Playback and export run the same `debut-render` graph; the audio clock in `debut-audio` is the master (PB-02).

These are checked on every `cargo test` and `cargo clippy` run, not just written down:

- **Layering** (`crates/debut-arch`): reads `cargo metadata` and fails when a crate depends on a higher layer, an engine-side crate depends on a platform implementation, a shell uses a feature crate instead of `debut-engine` or the other target's platform, the foundation picks up anything beyond serde/thiserror, or an OS / codec / GPU / UI-runtime crate (FFmpeg, cpal, Tauri, wasm-bindgen, wgpu, fontdue) appears outside its one home. A new crate fails until it is placed in a layer in `debut_arch::layer_of`. A second test proves each rule catches its violation.
- **No direct OS access** (`clippy.toml`): engine-side crates may not call `std::fs`, `std::path::Path::exists`/`is_file`/`is_dir`, spawn threads or read `Instant`/`SystemTime`; use `Platform::file_store`, `spawn` and `now`. The platform implementations and shells opt out with their own `clippy.toml`; test code that needs the OS says so with `#[allow(clippy::disallowed_methods, clippy::disallowed_types)]`. Clippy caches results, so after editing `clippy.toml` touch a source file (CI starts clean).

## Code layout

Where new code goes, so the shells stay thin:

- **Editing operations and their DTOs** go in `debut-engine/src/api/`, one module per area (`media`, `timeline`, `titles`, `multicam`, `playback`, `effects`, `mixer`, `export`, `markers`, `captions`), each adding methods to `Session`. Shared helpers and the session lifecycle live in `api/mod.rs`.
- **Anything OS-, codec- or device-specific** goes behind `debut_platform::Platform` (decoders, encoders, audio out, files, hardware queries). `Session` holds an `Arc<dyn Platform>`; `NativePlatform` is the desktop implementation.
- **Shells only translate.** `apps/desktop/src/ipc.rs` is one-line Tauri command forwards plus binary frame responses; it should not grow logic. The web shell will expose the same `Session` over wasm-bindgen.
- **Pure algorithms** (masks, tracking, loudness, sync, SRT, templates) live in the domain crates with their own unit tests; `Session` only wires them to the project and the player.
- **Session tests** are in `debut-engine/src/api/tests.rs`: one focused test per area over the native platform and the FFmpeg fixture, each starting from the shared `fixture()` project.

46. ~~Plugin hosts~~ Done: `debut-plugin-host` is a helper process (Service layer) that loads plugins, so a crash takes down only the helper; `NativePluginHost` talks to it over stdin/stdout (a JSON line per `Request` / `Reply` from `debut_platform::plugin_host`, then raw f32 samples), keeps separate helpers for video, audio and scanning, starts a fresh one after a crash and scans one binary per request (a binary that fails or crashes is listed as a problem). The OpenFX host (`csrc/ofx_host.c`, C because the parameter suite is variadic) implements the property, image effect, parameter, memory, multithread and message suites for filter/general-context effects: premultiplied RGBA at render scale 1, float or converted to 16/8-bit for plugins that want it, flipped to OpenFX's bottom-up rows. The CLAP host (`csrc/clap_host.c`) runs stereo effects with parameter changes as events. In the app: `Effect::Plugin` (parameters are keyframable curves) becomes a `Node::Plugin` that reads the layer back, calls `FrameProvider::plugin` and uploads the result (passing the layer through and reporting the error if the plugin fails); `AudioEffect::Plugin` track inserts run through `debut_audio::plugin` (one instance per insert, bypassed after a failure until the next reset) in playback and export. "+ Plugin" in the Inspector and "+ plugin" on mixer strips, with scan, parameters and errors. Tested with C test plugins built by build.rs (orientation, parameters, a deliberate crash, a broken binary) and checked by hand against OpenFX's Gain and Invert examples (raw API, 8-bit) and its C++ support-library Invert, and CLAP's plugin template. Not hosted: VST3 (a C++ COM-style ABI needing its own host), AU (macOS only), OpenFX overlays/interacts, GPU render (OpenGL/CUDA/Metal), multi-input and transition contexts, temporal clip access; the helper builds on Unix only. Ship the helper next to the app executable (or point `DEBUT_PLUGIN_HOST` at it); plugins are found on `DEBUT_PLUGIN_PATH`, `/usr/OFX/Plugins`, `~/.clap` and `/usr/lib/clap`.
47. ~~AAF export~~ Done: `debut_media::aaf` writes the sequence as an AAF file. Our own compound-file writer (`aaf/cfb.rs`: MS-CFB v3, mini stream, balanced red-black directory trees, DIFAT) holds AAF objects serialized like the SDK and pyaaf2 do: a storage and `properties` stream per object, index streams for strong and weak collections, and the `referenced properties` table. The MetaDictionary (the whole object model) and the Dictionary (data and operation definitions) come from `baseline.json`, generated with pyaaf2 by `tools/aaf_baseline.py` (MIT, license alongside). Each media file becomes a file SourceMob with picture/sound descriptors and a network locator, plus a MasterMob. Each sequence becomes a CompositionMob: one slot per track (padded to the sequence length) plus a timecode slot and a marker event slot; nested sequences are lower-level compositions. Clips are SourceClips, gaps and titles are Fillers, and dissolves are Transitions whose neighbours are lengthened by the overlap. The "AAF" button sits in the export panel. Checked by reading the file back with pyaaf2 (every property, mob references resolved to file paths, the dissolve's operation definition found) and with OpenTimelineIO's AAF adapter (same cut, source ranges and dissolve split; the marker attaches, though to the nested sequence's V1 because of the adapter's slot lookup). Not checked in Media Composer, Pro Tools or Resolve. Not written: speed changes, clip effects and audio levels, clip markers, and audio slots per channel (one stereo slot per file).
48. ~~Hardware decode~~ Done: `debut_platform_native::hwdecode` gives the decoder an FFmpeg hardware device before it opens. It tries VAAPI, then CUDA/NVDEC, then Vulkan on Linux; VideoToolbox on macOS; D3D11VA, CUDA or DXVA2 on Windows; `DEBUT_HWACCEL` overrides the list. libavcodec then negotiates the device's surface format. If the driver turns the stream down, libavcodec drops that format and decodes in software. Device frames are copied to system memory, and the scaler follows the frame's actual format. `Decoder::decode_path` reports `Requested` (until a frame is decoded), `Hardware(api)` or `Fallback { reason }`. `Platform::set_hardware_decode` and `Session::set_hardware_decode` reopen the player's decoders; `hardware_decode_status` lists each open media's path. An "HW decode" switch sits by the preview picker, turning amber with the reason on fallback. Off by default. Tested without a GPU: Mesa's software Vulkan device opens and is attached, its driver turns H.264 down, and the frames match software decoding. An API FFmpeg lacks falls back with that reason.
